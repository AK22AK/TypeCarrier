# 技术说明

本文描述 0.2.0 源码的主要实现；设备、网络和目标应用兼容性需单独验证。

## 组件与传输

- iOS：SwiftUI 输入界面，通过 `Network.framework` 发现并连接 Mac，走 v2 协议。连接状态由图标表达；具体设备名称保持单行正常字号，超过副标题可用宽度时尾部省略，不改实际设备名，无障碍保留完整名称与状态。截断由宽度决定，没有统一的字符数保证。首页始终保留系统导航栏，从子页面返回时标题栏不跳动；历史、设置等四个根页面共用一条导航路径，重复点击入口不会叠加页面。历史页推入时直接以展开的大标题显示，副标题为记录数；多台 Mac 在线时，目标入口为无底色的文字加右箭头。
- Android：原生输入界面，通过 NSD / mDNS 发现 Mac，走 v2 协议；自动发现失败时支持手动输入地址连接。
- macOS：SwiftUI + AppKit 菜单栏接收端，用一个 v2 监听器同时接收 iPhone 和 Android。
- Rust 协议核心（`Core/carrier-core`）：分帧、版本协商、Noise 握手、配对码、心跳和加密消息，三端共用同一份实现。Apple 端通过 UniFFI 生成的 Swift 绑定调用（`Sources/TypeCarrierCore/Generated`，静态库打包为 `Core/build/CarrierCoreFFI.xcframework`）；Android 通过 UniFFI 生成的 Kotlin 绑定经 JNA 调用 `libcarrier_core.so`。原生代码负责界面、设备发现和 socket，核心不做网络 I/O。
- TypeCarrierCore（Swift）：共享 payload、回执、连接状态、记录存储，以及基于 Rust 核心的 Apple 端 v2 连接（`CarrierV2Link`、`CarrierV2Client`）。

### v2 协议

- 发现：Mac 通过 Bonjour 广播 `_typecarrier-v2._tcp`，TXT 记录携带稳定设备 ID（`id`）和协议版本（`proto`）。默认监听端口 `17642`，被占用时改用系统分配端口，由 Bonjour 公布；Mac 的“高级信息”列出本机地址与端口，供 Android 手动连接使用。
- 分帧：每一帧为 4 字节大端长度前缀加负载，单帧最多 1 MiB。
- 连接过程：双方先各发一个明文 `Hello`（`proto` / `minProto` / 模式 / 平台 / 能力，取双方都支持的最高版本，当前只有 2）；再做 Noise 握手，配对用 `Noise_XX_25519_ChaChaPoly_SHA256`，已配对设备重连用 `Noise_IK_25519_ChaChaPoly_SHA256`。两个 `Hello` 都绑定进 Noise prologue，被篡改时握手失败。设备 ID 与名称在握手负载内加密传输。
- 握手后为加密的 JSON 消息，按 `type` 区分：`envelope`（应用层 payload 与回执，结构由应用定义）、`ping` / `pong`、`pairingConfirmed` / `pairingRejected`、`close`（附关闭原因，如 `notPaired`、`pairingRejected`、`replaced`、`heartbeatTimeout`）。
- 心跳：每 10 秒发一次 `ping`，对方 25 秒无任何数据即判定断开。

### 配对与信任

- 配对由手机发起：在手机上选择未配对的 Mac 并点“配对”，Mac 主窗口弹出确认框。两端显示同一个 4 位配对码，由 Noise 握手哈希派生，中间人会导致两端数字不同。用户核对后在 Mac 上点“允许”或“拒绝”；60 秒无人响应即作废，被拒绝后可立即重试。
- 每台设备有一把长期 Noise 身份密钥。Apple 端的私钥和已配对设备列表都保存在 Keychain（`AfterFirstUnlockThisDeviceOnly`）；Android 用 Android Keystore 中不可导出的 AES-GCM 密钥加密后存入 SharedPreferences。重新生成身份密钥会使所有配对失效；重新配对会替换对方的旧公钥。

### 搜索与多设备

- 手机搜索有时限：15 秒内没有连上任何设备就停止，显示“未找到设备”和重试；从后台回到前台时放宽到 25 秒。已发现但未配对的设备会在首页提示，而不是报“未找到”。设备列表打开期间保持搜索；Android 进入后台时停止发现并释放组播锁。
- 手机为每个已配对的 Mac 维持独立连接，可同时连接多台，但每次发送只路由到唯一选定目标。iPhone 在当前目标断开时，自动改选仍在线且本轮最早连接成功的 Mac，只影响后续发送；Android 保持离线目标不自动替换的规则。Mac 允许多手机接入，来源按稳定设备 ID 区分，同名设备不合并。
- 连接失败时界面显示可读的提示，原始网络错误只写入诊断日志。手机端把接收端统一称为“设备”。

## Mac 入口与生命周期

Mac 常驻菜单栏，无管理窗口的冷启动不显示 Dock 图标，也不自动弹窗。通过菜单中的“打开 TypeCarrier”、快捷键或 Finder / Launchpad 打开管理窗口时，显示 Dock 图标；最小化仍保留 Dock，可从 Dock 恢复。点 × 关闭最后一个管理窗口后隐藏 Dock，菜单栏与接收服务继续运行；仅明确退出应用才停止。接收与自动粘贴不主动激活管理窗口。

SwiftUI 通过 `NSApplicationDelegateAdaptor` 接入应用代理，菜单栏使用适用于多场景的 `isInserted` 构造方式。窗口打开回调由菜单栏入口注册，不依赖管理窗口先出现；早到的重开请求在回调就绪后处理。

## 设备显示名称

iOS 与 Mac 的名称设置默认显示完整生效名称和系统／自定义来源，点击编辑后才修改本地草稿；取消、离开页面或关窗不保存草稿。去除首尾空白后保存；保存空白名称，或选择“使用系统名称”后再保存，才清除自定义覆盖并回退到系统名称；取消会放弃这次来源选择。名称与稳定设备 ID、bundle variant、配对凭据分开管理，改名不改过去历史中的来源名称。名称在每次建立会话时随握手传给对方，对方据此更新已配对列表中的显示名称；已发消息不迁移或自动重发。

名称提示建议中文约 10 字、英文约 18 个字符，仅为易读建议，不限制保存。测量参考为现有 17／14 pt 字号与 375 pt 屏宽：14 pt 下 10 个中文样本约 139 pt、20 字符英文样本约 146 pt，而紧凑连接副标题约有 144 pt 文本空间；20 个 W 约 272 pt，20 个 i 约 70 pt，因此不能承诺固定字符数以内不省略。

完整名称保存在偏好中。Bonjour 服务实例名最多 63 个 UTF-8 字节，超长名称按不拆字素的方式截断作为发现时的别名（为空时用 `TypeCarrier`）；连接建立后以握手中传来的完整名称为准。参见 [DNS-SD 规范](https://www.rfc-editor.org/rfc/rfc6763#section-4.1.1)。

## 发送与粘贴

1. 手机保存发送记录，将文本 payload 只发给选定的 Mac。单次发送最多 9,999 个字符，接近上限时显示字数。
2. Mac 原子保存接收记录，立即向原连接返回 `received` 确认；保存失败不确认，手机保留文本。
3. Mac 将任务加入统一 FIFO，iPhone、Android 和本机手动粘贴共享同一队列，按到达顺序执行。
4. 每个任务在执行时快照剪贴板，写入文本、发出 Command-V，并按要求发出 Return；启用恢复时等待恢复完成后才执行下一条。恢复前检查 changeCount，不覆盖用户或其他应用期间复制的新内容。
5. 粘贴结果更新 Mac 历史，不作为手机清空的门槛，也不另发第二个完成回执。手机收到匹配接收确认后清空；未确认或传输失败时保留。

粘贴发送不等于目标 App 已输入。Mac 无法对所有应用可靠验证插入，用户可从接收历史复制或重新粘贴。旧无设备 ID 的 payload/历史仍可读取；来源信息优先使用连接身份，不能把任意旧版 ack 当成持久化保证。

Mac 提供剪贴板恢复开关，启用时尝试恢复原内容；不覆盖期间被用户或其他应用改动的新剪贴板。自动粘贴需要辅助功能权限，结果依赖当前焦点和目标应用。仅复制到剪贴板与确认后粘贴模式尚未实现。

## 本地记录与诊断

iOS 草稿和发送历史分别存储。草稿固定最多新增到 99 条，不自动淘汰；旧数据迁移时超过限额仍保留，只阻止继续新增。发送历史保留策略二选一：条数 100/200/500/1000（默认 200），或时间一周/一个月/半年/一年；时间模式按记录创建日期计算，不叠加条数上限。启动、回到前台、写入历史和修改设置时清理；设置变更立即生效。两类记录支持单条删除和独立清空。

迁移直接读取旧 `ios-records.json` 的完整记录，分流并成功写入两个文件后才移除旧文件；写入失败保留原文件供重试。历史按当前策略清理，草稿不参与清理。无法恢复已被旧存储逻辑删除的记录。

Mac 继续使用原有 `CarrierRecordStore`，接收历史默认保留最近 200 条并支持单条删除。本轮不改变 Mac / Android 行为。搜索和多选删除尚未实现。

连接状态、自检和诊断导出已有实现。历史记录和诊断日志保存在本地，无云账号或服务器中转；日志导出不能等同于历史备份。

## 限制

- 受限网络可能影响局域网发现或连接；Android 可尝试手动地址连接。
- 某些目标应用拒绝粘贴或无法验证插入；密码框和安全输入框不作为目标。
- 剪贴板中的富文本或延迟提供的数据可能无法完整恢复。
- 手机听写使用系统或第三方输入法，TypeCarrier 不控制其识别过程。

发送策略、自检和多设备候选方案见 [路线图](roadmap.md)。


## Mac 管理界面

- 常驻侧栏提供接收列表、连接管理、接收设置、诊断与测试、关于。接收列表保留记录列表与详情两栏，详情默认为阅读态；其他页面使用单内容区，功能测试由诊断页进入并可返回。
- 菜单栏只显示接收状态与管理入口、异常处理和退出。管理入口会选择对应页面；测试粘贴、接收器重启和诊断导出在管理页面操作。
- 新窗口以本机系统设置当前恢复窗口为参考，默认外窗 740 × 609 逻辑点（不是 Apple 官方固定默认值）。三列下限适配 740 点宽度，字号保持不变；侧栏与记录列可拖动，窗口仍可拉大。此尺寸更新只首次调整现有管理窗口，随后用 AppKit 保存和恢复用户手动尺寸，不清除其它偏好。布局不按截图的 2× 物理像素计算。
- 记录预览为两行，来源同名时才附短身份提示；完整稳定身份与正文仍按原格式保存。删除需确认。
- 详情阅读态以可选中的纯文本显示正文，字号与详情宽度不变，仅略增行距。点“编辑”后才进入占满详情区的输入框，需显式“保存”或“取消”；元数据头部在两种状态下保持一致。有未保存修改时，切换记录或页面、关闭管理窗口和退出应用都会先确认。保存失败或记录已被淘汰时保留编辑框中的文字；记录缓存只在写入磁盘成功后才更新。
- 没有在线设备且接收入口可用时显示正常等待，并展开“连接新设备”指引：iPhone 与 Android 都在手机上发起配对，Mac 弹出请求后核对数字并允许。局部入口异常与全部不可用分别显示；辅助功能权限只影响自动粘贴，不作为接收可用性的依据。
