# TypeCarrier 0.2.0 Beta

[中文](https://github.com/AK22AK/TypeCarrier/blob/master/docs/releases/0.2.0.md)

Release notes date: 2026-11-13. Actual availability depends on each distribution channel.

## Important: update all three apps together

0.2.0 moves to a new v2 transport protocol and is **not compatible with 0.1.x**:

- iPhone, Android and Mac all need 0.2.0; old and new versions cannot connect to each other.
- Existing connections and pairings are not kept. After updating, pair once again from the phone.

## What's New

**New encrypted transport**

- iPhone no longer uses Multipeer Connectivity and Android no longer uses its previous local channel. All three apps now use the v2 protocol: a direct local-network connection, end-to-end encrypted with a Noise handshake.
- The protocol core is written in Rust and shared by iPhone, Mac and Android, so both ends behave the same.
- Device identity keys and pairings are kept in the system's secure storage (Keychain on Apple platforms, Keystore-encrypted on Android).

**Pairing**

- The phone now starts pairing: pick the Mac on the phone and tap "Pair". The Mac shows a request, both screens show the same 4-digit number, and you tap "Allow" on the Mac once they match.
- A request with no response expires after 60 seconds; after a rejection you can retry right away. Once paired, devices reconnect automatically.
- The Mac no longer has a "Start Pairing" button.

**Search and connection**

- Searching stops after 15 seconds without a connection (25 seconds when returning from the background) and shows "No device found" with a retry button, instead of spinning forever.
- Devices that are discovered but not yet paired are pointed out on the home screen.
- Connection failures show a readable explanation; raw network errors go only to the diagnostic log.
- The phone apps now call the receiver a "device".
- Android stops searching in the background to save battery, and the refresh button no longer starts pairing with unpaired devices.

**Other**

- One send is limited to 9,999 characters, with a counter near the limit.
- The Mac received list and diagnostics page are smoother; the empty list is top-aligned.
- The Mac Debug build keeps a single Accessibility permission entry.

## What to Test

1. First pairing after updating all three apps: matching codes, allow, reject, and retry after a timeout.
2. Reconnecting in daily use: after backgrounding, Mac restart or wake from sleep, and switching Wi-Fi.
3. The search timeout message and retry; the home-screen hint for unpaired devices.
4. Target selection and sending with several Macs / phones online.
5. On Android, connecting manually with the address shown under the Mac's "Advanced" section when discovery fails.

## Requirements

- iOS 26.0, macOS 26.0, Android 8.0 or later.
- Phone and Mac on the same local network.
- The Mac needs Accessibility permission to insert received text at the current focus.

## Release Scope

- iOS is tested through TestFlight.
- GitHub Release provides a release-signed Android APK and a Developer ID signed, notarized macOS DMG.
- Cloud sync, internet relay and Windows are not included. Mixed use across several real devices is still being validated; please report anything unusual.
