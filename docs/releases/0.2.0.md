# TypeCarrier 0.2.0 Beta

[English](https://github.com/AK22AK/TypeCarrier/blob/master/docs/releases/0.2.0.en.md)

版本说明日期：2026-11-13。实际发布状态以各分发渠道为准。

## 重要：三端需同时更新

0.2.0 换用了新的 v2 传输协议，**与 0.1.x 互不兼容**：

- iPhone、Android 和 Mac 都要更新到 0.2.0，新旧版本之间无法连接。
- 原有的连接和配对不会保留，更新后需要在手机上重新配对一次。

## 更新内容

**新的加密传输**

- iPhone 不再使用 Multipeer Connectivity，Android 不再使用原来的局域网通道；三端统一改用 v2 协议，经局域网直连，Noise 握手端到端加密。
- 协议核心用 Rust 实现，iPhone、Mac、Android 共用同一份代码，两端行为一致。
- 设备身份密钥与配对信息保存在系统安全存储中（Apple 端为 Keychain，Android 为 Keystore 加密）。

**配对**

- 改为由手机发起配对：在手机上选择 Mac 并点“配对”，Mac 弹出请求，两端显示同一个 4 位数字，核对一致后在 Mac 上点“允许”。
- 60 秒无人响应即作废；被拒绝后可以立即重试。配对完成后自动重连，不需要再输入。
- Mac 上不再有“开始配对”按钮。

**搜索与连接**

- 搜索 15 秒（从后台回来时 25 秒）没有连上就停止，显示“未找到设备”和重试，不再一直转圈。
- 已发现但还没配对的设备会在首页提示。
- 连接失败时显示可读的说明，原始网络错误只写入诊断日志。
- 手机端把接收端统一称为“设备”。
- Android 进入后台时停止搜索，减少耗电；刷新按钮不会对未配对设备发起配对。

**其他**

- 单次发送最多 9,999 个字符，接近上限时显示字数。
- Mac 接收列表和诊断页更流畅；没有记录时列表顶部对齐。
- Mac Debug 构建只保留一条辅助功能授权记录。

## 测试重点

1. 三端更新后首次配对：配对码是否一致，允许、拒绝、超时后重试。
2. 日常使用中的重连：切后台再回来、Mac 重启或休眠唤醒、切换 Wi-Fi 之后能否自动连上。
3. 搜索超时提示与重试；未配对设备的首页提示。
4. 多台 Mac / 多部手机同时在线时的目标选择和收发。
5. Android 自动发现失败时，用 Mac “高级信息”里的地址手动连接。

## 运行要求

- iOS 26.0、macOS 26.0、Android 8.0 或更新版本。
- 手机与 Mac 位于同一局域网。
- Mac 端需要辅助功能权限，才能把收到的文本插入当前输入焦点。

## 发行范围

- iOS 通过 TestFlight 测试。
- GitHub Release 提供 Android release 签名 APK，以及 Developer ID 签名并公证的 macOS DMG。
- 不包含云同步、互联网中转或 Windows 支持。多台真机混合使用仍在持续验证中，欢迎反馈异常。
